# custom-kobalte

Solid 2.0 (RC) + Vite 8 client app with file-system routing. This is **not
SolidStart**: the source has no `app.config.ts`, `index.html`, mount file, or
server. `@solidjs/vite-plugin` runs in `start: true` (client) mode, generates
the shell and entry around `src/App.tsx`, and prerenders the shell at build
time. Node >= 22.12.

## Workflow contract

All agents share this checkout; follow `workflow/README.md`.

- Start with `workflow/plan new <slug> "short title"`; fill the new plan and
  keep `Status`, `Updated`, and `Locks released` current. Use
  `workflow/status` to see plans and active locks.
- Acquire a lock before writing a shared path:
  `workflow/lock acquire <path> "reason" [--wait N]`. Never edit a path covered
  by another session's lock. Use `touch` for long tasks and
  `workflow/lock release <path>` when done.
- Use resource locks for shared operations: `@dev-server`, `@build`, `@deps`.
  `workflow/lock run @build "reason" -- <command>` acquires and releases
  automatically.
- Locks go stale after 60 minutes (`WORKFLOW_LOCK_STALE_MINUTES`); inspect with
  `workflow/lock list` and clear with `workflow/lock prune --apply`. Use
  `--force` only for stale locks. Acquire multiple paths in lexicographic order.
- Read-only work needs no lock. Put every temporary file, log, or scratch
  artifact in repo `tmp/` (prefer `tmp/<session-id>/`), never in system `/tmp`
  or scattered at the repo root. Clean up when finished.
- Record changed files, verification commands, and results in the plan before
  declaring the task done.

## Commands

- `npm run dev` — Vite on port 3000.
- `npx vitest run` — one-shot tests (`npm test` is watch mode). Add a path to
  run one file (`npx vitest run src/components/Counter.test.tsx`) or `-t
  "increments"` for one test.
- `npx tsc --noEmit` — typecheck. Vite build does not typecheck.
- `npm run build` — emits static `dist/client` (deploy this) plus a
  `dist/server` bundle; in client mode there is no server runtime to deploy.
  `npm run serve` previews the build.
- `npm run lint` — oxlint over `src` only. It currently fails before linting
  with `Cannot find module 'eslint'`: `eslint` is an unmet peer of
  `eslint-plugin-solid`. Add `eslint` as a devDependency to run it; do not
  rewrite the oxlint config around the error.
- Verification loop: `npx tsc --noEmit && npx vitest run && npm run build`.

## Routing

- Files under `src/routes` are routes (nested convention). A default export is
  the page; an exported `route` object supplies `preload`/config;
  `[...404].tsx` is the catch-all; `users.tsx` + `users/` makes `users/*`
  pages children of that layout. New files are picked up automatically.
- `src/router.ts` creates the one router and exports `Router` plus typed
  `paths`; use `paths.users(id)` for internal URLs. `file-routes.d.ts` is
  generated by `fileRoutes({ types: true })` — never hand-edit it.
- `<Router>`'s render prop is the outlet and must render `props.children`.
  The current `src/App.tsx` returns only a heading, so routed pages do not
  render; restore the outlet when working on the app shell.
- Keep `extensions: ['.jsx', '.tsx']` on the Solid plugin: filesystem routing
  emits `?pick=` module ids that the plugin must compile.
- There is no `src/Document.tsx`; the plugin uses its built-in document shell.
  Add one only to customize the HTML shell.

## Testing and styling

- Vitest config is in `vite.config.ts`: jsdom, `globals: false` (import
  `describe`/`test`/`expect` from `vitest`), jest-dom matchers from
  `vitest-setup.ts`, and `isolate: false` (module state is shared across test
  files).
- `src/components/Counter.test.tsx` is the reference pattern:
  `captureArtifact` + `expectNoDiagnostics` + `expectRerunBudget`. Keep rerun
  budgets tight or explain an increase.
- Tailwind v4 has no `tailwind.config.js`: `src/App.css` is just
  `@import 'tailwindcss'` and is imported by `src/App.tsx`. Class names must be
  complete literal strings; runtime-built names are not scanned.

## Repo notes

- Both `package-lock.json` and `pnpm-lock.yaml` exist. The npm lock matches the
  installed tree; the pnpm lock is older. Prefer npm for dependency changes to
  avoid divergence.
- Despite the name, no `@kobalte/*` package is installed yet.
- `.agents/` is a vendored skill library (hidden in `.vscode`), not app code.

# Solid 2.0 for agents

Solid is not React, and 2.0 is not 1.x. Pattern-matching from either is the
dominant bug source. Every name below is a `solid-js` export unless noted;
DOM APIs (`render`, `hydrate`, `Portal`, `dynamic`) are in `@solidjs/web`.

## Three rules

1. **Props are read, not destructured; pass values, not accessors.**
   - Wrong: `function C({ name }) {}` and `<C value={count} />`
   - Right: `function C(props) { return <p>{props.name}</p>; }` and `<C value={count()} />`
2. **`createEffect` takes two functions: compute (tracks), then apply (side effects).**
   - Wrong: `createEffect(() => { el.title = count(); });`
   - Right: `createEffect(() => count(), v => { el.title = v; });`
3. **Stores are written through the draft.**
   - Wrong: `setStore("user", "name", "B")` or `setStore(produce(s => ...))`
   - Right: `setStore(s => { s.user.name = "B"; });`

## 1.x → 2.0 corrections

Nothing in the left column exists in 2.0.

| Wrong (1.x)                                    | Right (2.0)                                                       |
| ---------------------------------------------- | ----------------------------------------------------------------- |
| `import { createStore } from "solid-js/store"` | `import { createStore } from "solid-js"`                          |
| `import { render } from "solid-js/web"`        | `import { render } from "@solidjs/web"`                           |
| `"jsxImportSource": "solid-js"`                | `"jsxImportSource": "@solidjs/web"`                               |
| `createEffect(fn)` (one argument)              | `createEffect(compute, apply)`                                    |
| `onMount(fn)`                                  | `onSettled(() => { setup(); return cleanup; })`                   |
| `createEffect(on(dep, fn))`                    | `createEffect(() => dep(), v => fn(v))`                           |
| `const [d] = createResource(id, fetchX)`       | `const d = createMemo(() => fetchX(id()))` under `<Loading>`      |
| `d.loading` / `d.error`                        | `<Loading>` or `isPending(() => d())` / `<Errored>`               |
| `refetch()`                                    | `refresh(d)` (`affects(d); refresh(d)` to read as pending)        |
| `<Suspense>` / `<SuspenseList>`                | `<Loading>` / `<Reveal>`                                          |
| `<ErrorBoundary>`                              | `<Errored fallback={(err, reset) => ...}>` (heals automatically)  |
| `<Index each={xs}>`                            | `<For each={xs} keyed={false}>`                                   |
| `batch(fn)`                                    | not needed: updates batch per microtask; `flush()` applies now    |
| `startTransition` / `useTransition`            | built-in transitions: `action(...)`, `isPending`, optimistic APIs |
| `createComputed`                               | `createMemo`, split `createEffect`, or `createSignal(fn)`         |
| `mergeProps` / `splitProps` / `unwrap`         | `merge` / `omit` / `snapshot`                                     |
| `produce`, `createMutable`, `modifyMutable`    | draft setters are the default in `createStore`                    |
| `createSelector`                               | `createProjection` (or `createStore(fn)`)                         |
| `<Ctx.Provider value={v}>`                     | `<Ctx value={v}>`                                                 |
| `classList={{ a: x() }}`                       | `class={{ a: x() }}` or `class={["base", { a: x() }]}`            |
| `use:dir={x}` / `attr:` / `on:` / `tabIndex`   | `ref={dir(x)}` / plain attributes / `onClick` / `tabindex`        |
| `onError` / `catchError`                       | `<Errored>` or `createEffect(c, { effect, error })`               |
| `from(source)` / `observable`                  | return an AsyncIterable from a computation                        |

Also:

- Reads lag writes: `setX(1); x()` still returns the old value until the
  microtask or `flush()`. In tests, `flush()` before asserting.
- No writes inside a memo, effect compute, or component body (dev throws).
  Write from event handlers, `onSettled`, or actions.
- No reactive reads at the top of a component body; read in JSX, a memo, or
  `untrack`. Flow callbacks (`<For>`, `<Show>`, `<Match>`) are owners, not
  tracking scopes: read their accessor arguments in JSX, not at the top.
- `<For>`: default gives a raw item and an index accessor; `keyed={false}`
  gives an item accessor and a plain number. `<Repeat>`: `i` is a number.
- `onClick={cond() ? a : b}` binds once; decide inside a stable handler.

## Primitives to reach for

| Primitive                                                          | Use                                                                                     |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `createSignal(0)` / `createSignal(() => fetchUser(id()))`          | plain signal / writable derived value, sync or async; read by calling it                |
| `createMemo(() => fetchX(id()))`                                   | read-only derived value; a Promise result is pending until it lands                     |
| `createProjection(async () => api.list(), [], { key: "id" })`      | read-only derived store with keyed reconciliation                                       |
| `createOptimisticStore(() => api.list(), [])`                      | store whose optimistic writes revert when the transition settles                        |
| `action(function* (x) { write(); yield api.put(x); refresh(d); })` | mutation with transition coordination; optimistic writes go inside                      |
| `until(() => confirmed(), { timeout })`                            | Promise that resolves when a predicate turns truthy; `yield` it in an action            |
| `isPending(() => d())`                                             | true while a change to `d` is in flight (input changed or `affects()` declared)         |
| `latest(d)`                                                        | peek at the in-flight value during a transition                                         |
| `refresh(d)`                                                       | re-ask the source after a server write; quiet unless preceded by `affects(d)`           |
| `<Loading on={id()}>` `<Errored>` `<Reveal>` `<Repeat>` `<For>`    | async boundary (`on` re-arms it), error boundary, sibling order, range list, keyed list |
